# Project Summary
Repro Suite is a bilingual product hub for discovering and opening six tools for research reproducibility and paper communication. It presents tool cards with screenshots, explains the reproduction workflow, and highlights an example result. The static site also includes a blog, language and theme controls, and links to each tool. It does not require a database or API keys.

# Project Module Description
- **Hub page:** Introduces the suite with a browser-frame hero, product metrics, six tool cards, a five-step reproduction workflow, an example result, and shared-backend information.
- **Tool directory:** Provides bilingual descriptions, audience labels, screenshots, and Open links for:
  - **Paper Repro Agent:** Reproduces a paper’s headline result through tolerance setting, code execution, a clean rerun, and an audit.
  - **Repro Lite:** Quickly checks a single claim using Python in the browser.
  - **Reading Companion:** Helps users read papers, save quoted notes, cite claims, and identify what could not be verified.
  - **IndexBoard:** Builds leaderboards from results or descriptions, including intervals and ties.
  - **Repro Desk:** Offers a human-checked reproduction request as a free pilot.
  - **Paper Explainer:** Turns a paper into a short cinematic explainer video. The first 20 seconds are free, and users can make a preview of their own paper. Intended for authors promoting a new paper and readers seeking a quick overview. Links to [Paper Explainer](https://paperexplainer-aiid.pub.atoms.world).
- **Screenshot assets:** Locally hosted WebP screenshots illustrate the tools; the hero uses overlapping browser frames for depth.
- **Language and theme controls:** English/Chinese and light/dark toggles; preferences persist between visits.
- **Blog:** Blog index and article pages with Markdown rendering and prerendering support.
- **Shared UI:** Reusable interface components and hooks for navigation, forms, dialogs, notifications, and responsive layouts.

# File Description Inventory
- `src/pages/Index.tsx`: Hub hero, metrics, six tool cards, process steps, example result, backend information, and footer.
- `src/lib/content.ts`: Bilingual tool descriptions, audience labels, and hub copy.
- `src/components/site/BrowserFrame.tsx`: Shared browser-style frame used to display product screenshots.
- `public/shots/`: Optimized WebP product screenshots, including `paperexplainer.webp`.
- `scripts/capture_shots.py`: Captures product pages and saves optimized screenshots.
- `src/App.tsx`, `src/main.tsx`: Application routing and entry point.
- `src/index.css`, `src/App.css`: Global design tokens and application styles.
- `src/pages/blog/`, `src/components/blog/`, `src/blog-routes.tsx`: Blog pages, article rendering, and routes.
- `prerender/`: Blog prerendering, sitemap generation, and helpers.
- `src/components/ui/`, `src/hooks/`, `src/lib/`: Shared UI, hooks, content, configuration, blog, API, and utility helpers.
- `plugins/` and root configuration files: Development safeguards, tests, and build, lint, styling, type-checking, and browser-test configuration.

# Technology Stack
- React and TypeScript
- Vite
- Tailwind CSS and PostCSS
- Lucide icons
- WebP product screenshots
- Playwright and ESLint
- Python Playwright and Pillow for screenshot capture
- Static site content; no database or API keys required

# Usage
From the frontend directory, install dependencies and start the development server:
```bash
cd app/frontend
npm install
npm run dev
```

Run lint and build checks:
```bash
npm run lint
npm run build
```

To refresh screenshots, use `scripts/capture_shots.py`. Screenshot capture requires Python Playwright and Pillow.
